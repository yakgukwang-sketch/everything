# 개발 캘린더 — 일일 정리 에이전트

오늘 한 일을 정리하고, 내일 할 일을 계획하고, 모든 변경사항을 커밋 & 푸시합니다.

## 입력
- $ARGUMENTS: 추가 메모나 내일 계획 힌트 (비어있으면 자동 분석)

## 작업

### 1단계: 오늘 한 일 분석
1. `git log --oneline --since="today 00:00" --author` 로 오늘 커밋 히스토리 확인
2. `git diff --stat HEAD~10` 로 최근 변경 파일 범위 파악
3. `git status` 로 아직 커밋 안 된 변경사항 확인
4. 변경 내용을 카테고리별로 정리:
   - 새 기능 (feature)
   - 버그 수정 (fix)
   - 크롤러/데이터 (data)
   - UI/프론트엔드 (web)
   - API/백엔드 (api)
   - 기타 (docs, refactor 등)

### 2단계: 미커밋 변경사항 커밋
1. 커밋 안 된 변경사항이 있으면:
   - 변경 내용을 분석해서 의미 있는 커밋 메시지 작성
   - 관련 파일끼리 묶어서 커밋 (한 덩어리면 하나로)
   - 커밋 메시지는 한국어로, 변경 내용을 요약

### 3단계: Git Push
1. `git push origin` 으로 리모트에 푸시
2. 푸시 실패 시 원인 분석 후 해결

### 4단계: 일일 리포트 작성
아래 형식으로 `docs/daily/YYYY-MM-DD.md` 파일 생성:

```markdown
# 📅 YYYY-MM-DD 개발 일지

## ✅ 오늘 한 일
- [카테고리] 작업 내용 요약
- [카테고리] 작업 내용 요약

## 📊 변경 통계
- 커밋: N개
- 변경 파일: N개
- 추가: +N줄 / 삭제: -N줄

## 📋 내일 할 일
- [ ] 계획 1
- [ ] 계획 2

## 💡 메모
- (사용자 입력이나 특이사항)
```

### 5단계: 리포트 커밋 & 푸시
1. 일일 리포트 파일을 커밋
2. 다시 푸시

## 규칙
- 커밋 메시지는 한국어
- `.env`, 시크릿 파일은 절대 커밋하지 않음
- 리포트는 `docs/daily/` 디렉토리에 날짜별로 저장
- 내일 할 일은 오늘 작업 흐름 + 사용자 힌트 기반으로 추론
