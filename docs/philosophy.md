# Everything — 철학

## 한 줄 정의
> 모든 로컬 서비스의 데이터와 결제를 API로 제공하고, 누구나 그 위에서 세일즈할 수 있는 플랫폼.

---

## 문제 인식

기존 플랫폼 기업들 (쿠팡, 배민, 야놀자, 오늘의집 등)은:
- CS, 디자인, 운영 등 거대한 비용 구조를 가지고 있고
- 그만큼 높은 수수료를 판매자와 소비자 양쪽에서 가져간다
- 플랫폼이 독점하는 구조 — 이익이 소수에게 집중된다
- **자체 경쟁이 없다** — 쿠팡은 독점이라 수수료를 내릴 이유가 없다

---

## Everything의 답

**데이터 + API만 제공한다.**

- 쇼핑 상품, 숙박, 배달, 인테리어... 각 버티컬의 데이터를 모은다
- 결제(payments)를 결합한다
- 디자인, CS, 운영은 하지 않는다
- 개발자/세일즈맨(에이전트)이 API를 가져다 자기 서비스를 만든다

**나는 "쿠팡이츠를 만들 수 있는 API"를 파는 것이다.**

---

## 핵심 비유

### 방송국 → 유튜브
MBC, KBS, SBS가 나눠먹던 파이를 유튜브가 열어서 유튜버들이 가져갔다.

### 플랫폼 기업 → Everything
쿠팡, 배민, 야놀자가 독점하는 파이를 Everything이 열어서 에이전트들이 가져간다.

---

## 핵심 철학

**플랫폼이 독식하는 돈을 유저(에이전트)들에게 분배한다.**

- 배민이 가져가는 중개수수료
- 쿠팡이 가져가는 마진
- 야놀자가 가져가는 수수료

→ 이걸 실제로 세일즈하는 사람들이 가져가게 한다.

---

## 수익 구조

```
소비자: 같은 물건을 더 싸게 산다
    ↓ 구매
에이전트: 수수료를 받는다 (자기가 정함, 단 쿠팡보다 비싸면 안 팔림)
    ↓ API 사용
Everything: API 호출 건당 과금으로 번다 (Gemini처럼)
```

- Everything은 거래 수수료를 받지 않는다
- 에이전트끼리 경쟁하니까 수수료가 자연스럽게 내려간다
- 결국 같은 물건을 가장 싸게 팔 수밖에 없는 구조
- 가격 경쟁이 안 되면 **전문성**으로 경쟁 (노트북 전문, 육아 전문, 큐레이션 등)

---

## 왜 쇼핑부터?

쇼핑은 진입장벽이 가장 낮다:
- **데이터**: 뽐뿌 같은 핫딜 커뮤니티에 이미 정리되어 있고, 네이버쇼핑 API/쿠팡 파트너스도 있다
- **결제**: 제휴 링크로 결제 인프라 없이도 수익 가능
- **물류/기사**: 필요 없음
- **법적 리스크**: 공개 API 사용이라 크롤링 이슈 적음

반박 중 "데이터 확보", "결제 통합", "기존 플랫폼 해자" 문제를 쇼핑에선 우회할 수 있다.

---

## 데이터 전략

데이터는 두 방향에서 들어온다:

### 방향 1: 외부 쇼핑몰 크롤링 (브릿지)
뽐뿌에 올라오는 딜 링크에서 **한국 주요 전자상거래 사이트 목록**을 자동 추출한다.
(롯데온, 쿠팡, 오늘의집, 11번가, G마켓, 무신사...)

뽐뿌 = 사람들이 실제로 쓰는 쇼핑몰을 알려주는 소스.
→ 그 사이트들의 상품을 직접 크롤링.

**단, 크롤링 데이터로는 에이전트가 돈을 벌 수 없다.**
남의 쇼핑몰 상품이라 수수료를 줄 주체가 없기 때문.
→ 초기에 상품 수를 채우기 위한 브릿지 역할.

### 방향 2: 셀러 직접 등록 (본질)
판매자가 Everything에 직접 상품을 올린다.
- 가격, 재고, 수수료를 셀러가 직접 관리
- 에이전트가 팔아주면 수수료 지급 → **에이전트가 돈을 버는 구조가 완성**
- 이게 있어야 돈이 흐른다

**크롤링은 셀러가 모이기 전까지의 브릿지. 최종적으로 셀러 직접 등록이 메인.**

---

## 구조

```
데이터 수집
├── 방향 1: 뽐뿌 → 쇼핑몰 목록 추출 → 각 사이트 크롤링
└── 방향 2: 셀러가 Everything에 직접 등록

Everything (인프라)
├── 데이터: 크롤링 + 셀러 직접 등록
├── 결제: 제휴 링크 → 추후 Payments API
├── API: 건당 과금, 누구나 접근 가능
└── 운영 비용: 최소 (데이터만 쌓으면 됨)

에이전트 (세일즈맨)
├── 각자의 방식으로 세일즈
├── 각자의 색깔, 전문성
├── 수수료를 자기가 정함 (셀러 등록 상품 → 셀러가 수수료 지급)
└── 경쟁 → 소비자에게 유리한 가격
```

---

## 최종 목표

쿠팡이츠, 야놀자, 쿠팡, 배달의민족, 오늘의집 등
모든 플랫폼 기업의 결제(payments)를 하나의 API로 통합하고,
그 위에 에이전트 생태계를 만들어 네트워크 효과를 일으킨다.

---

## 비판할 점 / 풀어야 할 질문

1. **데이터 품질** — 뽐뿌/크롤링 데이터로 쿠팡 수준의 상품 정보를 제공할 수 있나?
2. **닭과 달걀** — 에이전트가 없으면 소비자가 안 오고, 소비자가 없으면 에이전트가 안 온다
3. **유튜브는 구글이었다** — 인프라만으로 사람이 모이진 않는다. 초기 트래픽은 어디서?
4. **기존 플랫폼의 반격** — 쿠팡이 API 접근을 막으면?
5. **API 과금만으로 수익이 되나?** — 에이전트가 충분히 많아야 의미 있는 매출
6. **수수료 경쟁의 바닥** — 에이전트끼리 너무 경쟁하면 아무도 못 벌 수 있다

## 발전시킬 방향

### 지금 해야 할 것
1. **데이터 쌓기** — 상품 갯수가 많아야 에이전트가 할 일이 생긴다
   - 뽐뿌 크롤러: 한국 주요 쇼핑몰 목록 자동 추출
   - 추출된 쇼핑몰별 크롤러 확장
2. **셀러 등록** — Everything에 상품을 올릴 수 있게
   - 이래야 에이전트에게 수수료를 줄 수 있다
   - 에이전트가 돈을 버는 구조의 시작점
